# Truco Online — effective delivery contract

The versioned policy is `.hermes/team/process-policy.json`. Runtime permissions
are enforced by the controller, not by this document, chat, memories or a role's
seniority. Model fallback is forbidden. Mobile is inactive for web-only releases.

- CEO owns product intent, user questions, scope, credentials and explicit security exceptions.
- Product owns discovery and acceptance. Tech Lead owns flow and integration.
- CTO owns architecture, technical impasses and high-risk reviews, not every microtask.
- Specialists execute only admitted capabilities. Missing capability is platform work, not permission to improvise privileged commands.
- One active release; at most two workers and one per profile. Dependency-ready work ages in the queue. A finite execution budget never cancels a release.
- Handoffs require durable source, recipient, revision, evidence and next action. Telegram is a notification/interface, not the authority to complete work.
- Feedback includes the full independent review. Preserve drafts/checkpoints; never restart the same failed hypothesis indefinitely.
- Shared knowledge requires source, scope, expiry and independent curation. Superseded or other-attempt evidence is not current authority. Personal memory contains no secrets, backlog or permissions.
- Behavioral work uses relevant Red, Green and the full suite. Existing baseline cases must remain exercised. Pure refactors use characterization and green before/after, never fabricated Red.
- No unilateral skipped/focused/deleted/weakened tests or reduced discovery. Technical maintenance requires an exact reviewed proposal, case mapping, execution evidence and controller attestation. Product scope changes still require product authority.
- Reviewer never edits the author's delivery or reviews their own work. Approval binds to the exact artifact, execution and base. Base changes require revalidation and fresh review.
- Snapshot approval is not integration. CI and independent exact-head review are mandatory before normal merge. No force push or silent guard bypass.
- Local Docker only. Workers/test containers receive no infrastructure credentials or Docker socket. The trusted controller performs fixed privileged operations.
- A release is successful only at HOMOLOGADA with complete approved scope, matching commit/CI/deploy/QA, healthy services, rollback evidence and a usable URL. Lobby progress alone does not finish v0.1.

The one-time governance migration authorized on 2026-09-19 does not authorize
exceptions for product PRs. Historical records and receipts remain auditable.
